# C 环境配置：VS Code + MSYS2 UCRT64

> 适用：Windows 10/11，已安装 VS Code，想用 GCC 跟课学 C。
> 这份文档按你机器上的实际情况写：`Cproject/.vscode` 已经按 `gcc` + `gdb` 配好，但系统里还没有编译器。

---

## 0. 先说结论

**推荐：VS Code + MSYS2 的 UCRT64 版 GCC。**

理由：

- 你现有的 `.vscode/tasks.json`、`launch.json` 就是按 `gcc` / `gdb` 写的，装完不用改代码；
- MSYS2 自带 `pacman`，以后装 `gdb`、`make`、`cmake` 都是一条命令；
- UCRT64 是 MSYS2 现在推荐的环境，运行时兼容性比老 MINGW64 好；
- 比 Visual Studio 轻很多，比 Dev-C++ 新很多，比 WSL 少一层。

**备选：WinLibs 解压版**（不想装 MSYS2 时，见第 7 节）。
**不推荐默认用**：Dev-C++（自带 GCC 太旧）、Visual Studio（体积大，且和现有 GCC 配置不兼容）、WSL（多一层，初学 C 没必要）。

> 如果老师明确要求 Dev-C++ 或 Visual Studio，先按老师的要求；GCC 写的标准 C 代码本身是通用的，提交 `.c` 文件不受影响。

## 1. 你现在的状态

| 项目 | 状态 |
|---|---|
| VS Code | 已安装（1.143.0） |
| `Cproject/.vscode` | 已配置 `gcc` / `gdb` 任务 |
| `gcc` / `gdb` / `cl` | **都没有** |
| C/C++ 扩展 | **未安装**（扩展目录里只有 Python 和中文语言包） |
| 结果 | 按 `Ctrl+Shift+B` 会报“gcc 不是内部或外部命令” |

所以只差两步：**装编译器** + **装 VS Code 的 C/C++ 扩展**。

## 2. 安装 MSYS2

### 2.1 下载

- 官网：<https://www.msys2.org/>
- 国内如果慢，可以用清华镜像的 `msys2/distrib/` 目录：<https://mirrors.tuna.tsinghua.edu.cn/msys2/distrib/>
- 下载 `msys2-x86_64-*.exe`。

### 2.2 安装

- 双击安装，路径保持默认 **`C:\msys64`**；
- 不要装在带空格或中文的路径里（例如 `C:\Program Files`、`D:\我的软件`）；
- 安装完成后，开始菜单里会有几个 MSYS2 终端，选 **“MSYS2 UCRT64”**（不是 “MSYS2 MSYS”，也不是 “MINGW64”）。

### 2.3 更新软件源

在 UCRT64 终端里执行：

```bash
pacman -Syu --noconfirm
```

如果它提示“关闭终端后重新打开”，就关掉窗口，重新打开 **MSYS2 UCRT64**，再执行一次：

```bash
pacman -Syu --noconfirm
```

### 2.4 安装 GCC、GDB、Make

```bash
pacman -S --needed --noconfirm mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-gdb mingw-w64-ucrt-x86_64-make
```

装完在同一个终端里验证：

```bash
gcc --version
gdb --version
mingw32-make --version
```

三条都能打印版本号，就说明编译器装好了。**注意**：这里装的是 `mingw32-make`，不是 `make`；单文件编译暂时用不到 make。

## 3. 把 GCC 加进 PATH

MSYS2 的 UCRT64 终端里能用，不代表 VS Code 的 PowerShell 里能用。需要把 `C:\msys64\ucrt64\bin` 加到**用户 PATH**。

### 方法 A：图形界面

1. `Win + R` 输入 `sysdm.cpl`，回车；
2. “高级” → “环境变量”；
3. 在上半部分“用户变量”里选中 `Path` → “编辑”；
4. “新建” → 粘贴 `C:\msys64\ucrt64\bin` → 一路“确定”。

### 方法 B：PowerShell（推荐，能避免重复添加）

```powershell
$bin = 'C:\msys64\ucrt64\bin'
$path = [Environment]::GetEnvironmentVariable('Path', 'User')
if (($path -split ';') -notcontains $bin) {
    [Environment]::SetEnvironmentVariable('Path', ($path.TrimEnd(';') + ';' + $bin), 'User')
}
```

然后**完全关闭 VS Code 和所有终端窗口，再重新打开**（PATH 是进程启动时读的，不重启不生效）。

验证：

```powershell
where.exe gcc
gcc --version
gdb --version
```

`where.exe gcc` 应该输出 `C:\msys64\ucrt64\bin\gcc.exe`。

## 4. 配置 VS Code

### 4.1 安装 C/C++ 扩展

在 VS Code 扩展面板搜索 **C/C++**，作者是 Microsoft，扩展 ID 是 `ms-vscode.cpptools`。

或者用命令行：

```powershell
code --install-extension ms-vscode.cpptools
```

### 4.2 打开正确的文件夹

**用 VS Code 打开 `Cproject` 文件夹本身**：

```text
D:\Coding Exercises\Cproject
```

不要只打开 `D:\Coding Exercises`，否则 VS Code 找不到 `Cproject/.vscode` 里的任务和调试配置。

### 4.3 检查 `.vscode` 路径

我已经把三个文件里的路径改成 MSYS2 默认安装位置：

- `.vscode/c_cpp_properties.json` → `C:/msys64/ucrt64/bin/gcc.exe`
- `.vscode/tasks.json` → `C:\msys64\ucrt64\bin\gcc.exe`
- `.vscode/launch.json` → `C:\msys64\ucrt64\bin\gdb.exe`

如果你把 MSYS2 装到了别的盘（例如 `D:\msys64`），把这三处改成对应路径即可。

### 4.4 编译与调试

- `Ctrl + Shift + B`：选择 **“编译当前文件”**，生成同名的 `.exe`；
- 再按一次，选择 **“编译并运行”**，会编译后直接运行；
- 打开一个 `.c` 文件，按 `F5`：用 `gdb` 调试（需要先编译成功）。

## 5. 一键验证

在 `Cproject` 目录打开 PowerShell：

> **注意**：是“运行这个 `.ps1` 文件”，不是把文件内容逐行粘贴到 PowerShell。粘贴执行时 `$PSScriptRoot` / `$MyInvocation.MyCommand.Path` 是空的，脚本会算不出项目路径，`hello.c` 就变成空字符串。

```powershell
cd 'D:\Coding Exercises\Cproject'
powershell -ExecutionPolicy Bypass -File .\verify-c.ps1
```

脚本会检查 `gcc` / `gdb`，编译并运行 `hello.c`。为了不和 VS Code 生成的 `hello.exe` 互相锁文件，脚本把测试用的 exe 放到临时目录；VS Code 的“编译当前文件”仍然输出到 `Cproject` 里。预期输出类似：

```text
[OK] gcc: C:\msys64\ucrt64\bin\gcc.exe
gcc (Rev...) ...
[OK] gdb: C:\msys64\ucrt64\bin\gdb.exe
...
Compiling D:\Coding Exercises\Cproject\hello.c -> C:\Users\...\AppData\Local\Temp\coding-etudes-hello.exe ...
Running C:\Users\...\AppData\Local\Temp\coding-etudes-hello.exe ...
hello, C
a / b = 3,  (double)a / b = 3.50

[OK] C toolchain is ready.
```

如果脚本能跑通，VS Code 里的“编译当前文件”也就没问题了。

## 6. 常见问题

### 6.1 `gcc : 无法将“gcc”项识别为 cmdlet...`

- PATH 没加，或者加完没重启 VS Code；
- 先在新 PowerShell 里跑 `where.exe gcc`；
- 如果 `where.exe` 找不到，但 `C:\msys64\ucrt64\bin\gcc.exe` 存在，检查 PATH 是否真的加到了“用户变量”；
- 还不行就直接用绝对路径测试：`C:\msys64\ucrt64\bin\gcc.exe --version`。

### 6.2 `pacman -Syu` 很慢或失败

- 换清华镜像：把 `/etc/pacman.d/` 下 `mirrorlist.*` 里的服务器改成 `https://mirrors.tuna.tsinghua.edu.cn/msys2/...`；
- 或者重试几次；
- 公司/学校网络有代理时，先确认代理设置。

### 6.3 `pacman -Syu` 提示关闭终端

这是 MSYS2 在更新自己。关掉窗口，重新打开 **MSYS2 UCRT64**，再执行一次 `pacman -Syu --noconfirm`。

### 6.4 找不到 `gdb`

```bash
pacman -S --needed mingw-w64-ucrt-x86_64-gdb
```

或者检查 `.vscode/launch.json` 里的 `miDebuggerPath` 是否指向 `C:\msys64\ucrt64\bin\gdb.exe`。

### 6.5 代码里 `#include <stdio.h>` 有红波浪线

- 确认装了 C/C++ 扩展；
- 确认 `c_cpp_properties.json` 的 `compilerPath` 指向真实存在的 `gcc.exe`；
- `c_cpp_properties.json` 里已经加了 `C:/msys64/ucrt64/include`，正常情况下 `stdio.h` 能解析；
- 在 VS Code 里按 `Ctrl+Shift+P`，运行 `C/C++: Select IntelliSense Configuration`，选 GCC；
- 还红：运行 `C/C++: Reset IntelliSense Database`；仍不行就完全关闭 VS Code，删除 `%LOCALAPPDATA%\Microsoft\vscode-cpptools\ipch` 再打开；
- 确认文件末尾有换行（最后一行没换行时，cpptools 偶发 `character must be non-negative`）；
- 临时兜底：设置 `C_Cpp.intelliSenseEngine` 为 `Tag Parser`，它只按 `includePath` 解析，不查编译器。

### 6.6 中文输出乱码

VS Code 默认把源文件存成 UTF-8。Windows 控制台默认代码页可能是 GBK（936），两者不一致就会乱码。

项目里的 `.vscode/tasks.json` 已经加了：

```text
-finput-charset=UTF-8
-fexec-charset=GBK
```

也就是“源文件按 UTF-8 读，运行时字符串按 GBK 输出”，适配 cmd/PowerShell 默认的 936 代码页。改完 **重新编译** 再运行即可。

其他情况：

1. 如果你把终端切到 UTF-8（`chcp 65001`）或使用 Windows Terminal 的 UTF-8 配置，要么把 `-fexec-charset=GBK` 去掉，要么运行前 `chcp 936`；
2. 课程作业里也可以尽量用英文输出，中文只放在注释里（注释不参与运行）；
3. 不要同时混用多种方案；先确认终端代码页，再选一种。

### 6.7 `undefined reference to 'WinMain'`

C 程序的入口写成：

```c
int main(void) { ... }
```

不是 `void main()`，也不是 `WinMain`。如果文件是 `.cpp`，用 `int main()`。

### 6.8 杀毒软件拦截 `hello.exe`

把 `D:\Coding Exercises` 和 `C:\msys64` 加进杀毒软件白名单/排除目录。

### 6.9 `make` 找不到

MSYS2 的 MinGW 包提供的是 `mingw32-make`，不是 `make`。单文件任务不需要 make；以后学多文件编译时用 `mingw32-make`。

### 6.10 C/C++ 扩展一直“正在安装”

现象：扩展面板里 C/C++ 一直显示“正在安装”，日志里 `ms-vscode.cpptools` 从某个时间点开始就没有下文；`%APPDATA%\Code\CachedExtensionVSIXs` 里有一个 **0 字节**的缓存文件。这通常不是扩展坏了，而是 **VSIX 下载卡住**（网络/CDN/代理），同时 VS Code 自己的更新也在抢下载。

处理顺序：

1. 保存所有文件，**完全退出 VS Code**（任务管理器里确认没有 `Code.exe`）。
2. 删除 0 字节缓存：
   ```powershell
   Get-ChildItem "$env:APPDATA\Code\CachedExtensionVSIXs" -File -Force |
       Where-Object Length -eq 0 |
       Remove-Item -Force
   ```
3. 临时关闭自动更新：在 `settings.json` 里加一行
   ```json
   "update.mode": "none"
   ```
   装好扩展后再改回 `"default"`。
4. 重新打开 VS Code，**只安装 `ms-vscode.cpptools`**（C/C++ 本体），不要再点 Extension Pack——pack 里的 Themes、DevTools、CMake Tools 已经装好了。
5. 如果缓存文件开始变大，说明在下载，等它完成；如果仍然是 0 字节，走第 6 步。
6. 手动下载 VSIX：
   - 市场页：<https://marketplace.visualstudio.com/items?itemName=ms-vscode.cpptools>
   - 右侧 “Resources” → “Download Extension”；
   - 或 GitHub Releases：<https://github.com/microsoft/vscode-cpptools/releases> 下载 `cpptools-win32-x64.vsix`；
   - VS Code 扩展面板右上角 `...` → **Install from VSIX...**，或：
     ```powershell
     code --install-extension "C:\path\to\cpptools-win32-x64.vsix"
     ```
7. 如果浏览器下载也卡在 0 字节，说明是网络问题：换手机热点/VPN，或等网络恢复；不是 GCC 的问题。

> 即使 C/C++ 扩展没装好，`Ctrl+Shift+B` 仍然可以直接调用 `gcc` 编译运行，红色波浪线只是 IntelliSense 缺失。先写代码、先编译，不被扩展卡住。

## 7. 备选：WinLibs 解压版

如果不想装 MSYS2，可以用 WinLibs 的独立包：

1. 打开 <https://winlibs.com/>；
2. 下载 **UCRT + POSIX + SEH + x86_64** 的 zip（例如 `winlibs-x86_64-posix-seh-gcc-...-mingw-w64ucrt-...zip`）；
3. 解压到 `C:\mingw64`（不要有空格/中文）；
4. 把 `C:\mingw64\bin` 加到用户 PATH（方法同第 3 节）；
5. 把 `.vscode` 三个文件里的 `C:\msys64\ucrt64\bin` 改成 `C:\mingw64\bin`；
6. 运行 `verify-c.ps1` 验证。

优点：不用装包管理器，解压即用。缺点：以后升级要手动换 zip，且下载源/版本要选对。

---

## 8. 为什么不是其他方案

| 方案 | 结论 | 原因 |
|---|---|---|
| Dev-C++ | 不推荐默认用 | 自带 GCC 很旧，调试器老；但老师强制时可用 |
| Visual Studio 2022 | 课程要求 MSVC 时才用 | 体积大，`cl.exe` 和现有 `gcc` 配置不兼容 |
| WSL2 + gcc | 想学 Linux 时再用 | 多一层环境，路径/图形调试对初学 C 偏重 |
| 多个 GCC 混装 | 不推荐 | `where gcc` 只认第一个，容易版本冲突 |

装好后把 `verify-c.ps1` 的输出发我，我帮你确认；如果哪一步报错，把完整错误贴过来即可。
